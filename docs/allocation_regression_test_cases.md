# 引当回帰テストケース（標準）

## 1. 目的

priority ベースの引当、部分出荷、引当解除、主要画面表示の整合を、毎回同一手順で回帰確認できるようにする。

## 2. 共通前提

- ローカルDB: `data/warehouse.db`
- 作業ブランチ: `feat/inventory-transactions-foundation`
- 現在戦略: `priority`
- priority順:
  1. priority 昇順
  2. 同priorityなら location_code 昇順
  3. priority が無いロケーションは後ろ

## 3. RG-001 priority優先確認

### テストID
RG-001

### 目的
priority が小さいロケーションから先に引当されることを確認する。

### 事前準備
- `PRIO-TEST-01` の在庫イベントを以下で作成しておく。
- 既存データの影響を避けるため、同一商品の不要な過去データが無い状態で実施する。

### 入力データ
- 商品: `PRIO-TEST-01`
- 在庫:
  - `A01 qty=2 priority=2`
  - `A02 qty=2 priority=1`
  - `A03 qty=2 priority=3`
- 出荷指示:
  - `PRIO-ORDER-01`
  - 明細: `PRIO-TEST-01,3`

3. 登録結果のロケーション別引当内訳を確認する。

### 期待結果

- `A01` から `1`
